Fundamentals of neural networks: actually build one

The companion guide derives the formulas. This one assembles them into a working digit classifier — every shape, every parameter, and a complete implementation in about sixty lines of NumPy. Twelve of the ideas below are live: change them and watch what happens.

forward — signal travelling in backward — blame travelling out loss — how wrong we were

Here is the finished machine. You are not meant to follow it yet — §1 starts from a single fitted line and builds up to exactly this.

01The mental model

A network is a function you fit to data

Strip away the vocabulary and a neural network is a function: numbers in, numbers out.

TaskInOut
Digit recognition784 pixel values10 class scores
House pricing12 property features1 price
Language modellinga sequence of tokensa score per possible next token

What makes it neural is that the function has millions of adjustable numbers inside it, and we don't set them by hand. We show it examples and let an optimization procedure find them.

So there are only ever two questions: what shape is the function, and how do we fit it. Sections 1–3 answer the first; sections 4–6 answer the second.

Three words carry the whole document, and it is worth pinning them down before anything else:

  • Training is fitting the function's numbers to data — searching for the m's and c's and W's that make the function's output match the data it's shown, by repeatedly measuring how wrong it is and nudging every number to be less wrong.
  • Inference is everything that happens after training: the numbers are frozen, and you plug in a brand-new input and evaluate the same equation once, forward, to get an answer.
  • Learning is the word for the iterative part of training itself — not one fit, but a loop of small equation-driven adjustments, each one nudging every number slightly toward a better fit, repeated thousands of times.

The smallest possible example of all three, with no neural network vocabulary at all, is fitting a line: y = mx + c is a function with exactly two adjustable numbers. Given some (x, y) points, training means searching for the m and c that make the line pass as close to all of them as possible; inference means plugging a new x into that one fixed line; learning means the loop that gets you there — start with a guess for m and c, measure how far off the line is, nudge both a little in the direction that reduces the error, repeat. Everything below is that same loop, just with a curvier function and 109,386 numbers instead of two. Watch it happen on a function curvy enough to need more than a line, before any of the machinery behind it is explained:

Nothing about why it moves the way it does has been explained yet — that is the rest of this document. Sections 2–5 build the shape of the function you just watched fit; sections 6–9 build the "nudge every number a little" step exactly, in equations, and section 7 runs the identical exercise on the real 784→128→64→10 model.

02The building block

The neuron is a tiny scoring machine

A neuron takes several inputs, weights each by importance, sums them, adds a bias, and passes the result through a nonlinear function.

z = w₁x₁ + w₂x₂ + … + wₙxₙ + b   ⟶   a = f(z)

It asks one question about the input and outputs one number saying how strongly the answer is yes.

What weights mean

Weights are what the model learns. Everything the network knows lives in them.

  • Large positive — this input strongly pushes the output up
  • Near zero — this input is ignored
  • Large negative — this input pushes the output down

A useful reframing: the weights are the model. Save them and you have saved everything; lose them and you have nothing but architecture.

The bias is the neuron's default answer before any evidence arrives. Without it, an all-zero input would be forced to produce zero, and every neuron's tipping point would be stuck at exactly zero.

03Layers

A layer is many neurons, and one matrix

One neuron gives one answer. We want many, so we run many neurons over the same input. Stack each neuron's weight vector as a row of a matrix and the whole layer becomes one multiplication:

h = f(Wx + b)

Each row of W is one neuron. One row = one question.

So if a layer takes 3 inputs and produces 4 outputs, it needs 4 neurons (4 rows), each weighing 3 inputs (3 columns): W is 4×3, and b has 4 entries.

With a batch. In practice you process 64 images at once, stacked as rows: X is 64×784. Then compute XWᵀ + b, giving 64×128. The single bias vector is added to every row automatically — that is broadcasting.

Hidden layers and what they are for

A hidden layer is any layer between input and output. "Hidden" only means we never observe its values directly. What makes them worth having is that they build intermediate representations:

raw pixels → edges → corners, curves → parts → whole objects

Each layer's output becomes the next layer's input, so later layers ask questions about earlier answers rather than about raw data. "Is there a loop in the top half?" is a far more useful question than "is pixel 341 bright?", and it can only be asked once something has already computed loop-ness. Nobody designs these features; they emerge because features that reduce the loss get reinforced.

04Nonlinearity

Without a kink, depth is an illusion

The obvious idea: if one layer is limited, stack more. But check what happens with plain linear layers:

W₂(W₁x + b₁) + b₂ = (W₂W₁)x + (W₂b₁ + b₂) = W′x + b′

One layer. Not "weaker than two layers" — mathematically identical to one. Stack a thousand and it still collapses.

So we put a kink between them. The standard choice is ReLU: negative → zero, otherwise pass through.

ReLU(x) = max(0, x)

One bend at the origin, applied to every number independently. That is enough: with enough bends you can trace any curve, and now the layers genuinely cannot be merged. Sigmoid and tanh were used historically but saturate — their derivatives shrink toward zero for large inputs, which stalls learning in deep stacks. ReLU's derivative is exactly 1 on the positive side, so signal passes through undamaged.

05The output end

Logits are not probabilities

The final layer has one neuron per class. For digits, ten neurons. Its raw output is a vector of unbounded real numbers called logits — they can be negative and do not sum to anything in particular. To get probabilities, apply softmax:

softmax(z)ᵢ = ezᵢ ⁄ Σⱼ ezⱼ
LogitsProbabilities
Rangeany real number[0, 1], summing to 1
Produced bythe last linear layersoftmax applied to logits

A bug that costs accuracy without ever crashing

Frameworks want logits passed to the loss, not probabilities — cross_entropy applies softmax internally in a numerically safer fused form. Applying softmax yourself and passing the result trains a worse model and never raises an error.

The loss

The loss is one number saying how wrong the prediction was. For classification we use cross-entropy, which is the model's surprise at the correct answer:

L = −log( probability assigned to the true class )
06Learning

Backpropagation, properly

The three-sentence version — "it sends the error backward" — is a description, not an explanation. Here is what actually happens.

The problem. The loss is one number. The model has 109,386 knobs. We need to know, for each knob: if I turn this up slightly, does the loss go up or down, and by how much? That list of answers is the gradient, and it is really a list of blame.

Forward: push the input through the layers, saving every intermediate value along the way. You will need them, and forgetting to save them is the most common from-scratch bug.

Backward: start at the loss and walk back through the layers, computing each one's share of the blame using the chain rule — rates of change multiply along a chain, like gears.

Why backwards and not forwards? Because there is one loss and a hundred thousand parameters. Starting from the single output and walking back gets every gradient in one sweep. Starting from each parameter and walking forward would need one sweep per parameter — a hundred thousand times more work. That asymmetry is the entire reason training is feasible.

Three facts make it concrete, for a layer y = Wx + b receiving blame δ from above:

∂L∂W = δ xᵀ     ∂L∂b = δ     ∂L∂x = Wᵀ δ

Read the first one in words: a weight's blame is (how wrong its output was) × (how active its input was). A weight can only be at fault if it was carrying signal. The third says blame flows back to the inputs through the same wires it came forward on — that is all the transpose is doing. You will see all three at work in the code in section 10 — though the code stores each example as a row, not a column, so multiplying by Wᵀ from the left becomes multiplying by W from the right; same operation, flipped layout.

Gradient descent

Once you know the blame, act on it:

W ← W − η · ∂L∂W
07The concrete model

Every shape, every parameter

784 → 128 → 64 → 10
  • 784 is not a choice. A 28×28 grayscale image has 784 pixels.
  • 10 is not a choice either. Ten digits, ten classes.
  • 128 and 64 are choices. They are the model's capacity, and nothing forces them.

The narrowing funnel is deliberate: each layer compresses toward increasingly abstract, task-relevant features. 784 raw pixels contain a lot of redundancy; 64 well-chosen features can be plenty to separate ten digits.

08What flattening costs

The dense layer never sees a picture

A dense layer takes a vector, so a 28×28 image gets unrolled into a 784-length list. This is not free.

In the image, pixel (0,0) and (1,0) are vertically adjacent. After flattening they land at index 0 and index 28 — and the dense layer has no notion that those positions are related. As far as it is concerned, all 784 inputs are an unordered bag of numbers.

The consequences are real. A digit shifted three pixels right is, to this model, a completely different input — it has to learn "3-ness" separately at every position. The model still works on MNIST because the digits are pre-centred and pre-sized. On less tidy images it falls over.

Dense (this model)Convolutional
Sees the 2D grid?No — flattened to a bag of numbersYes — a filter slides over rows and columns
Weights per patternOne full set per position that pattern can appear atOne small filter, reused at every position
Parameters for "detect an edge everywhere"Learned separately per position — expensive, and never guaranteed consistentOne 3×3 filter (9 weights) shared across the whole image
Robust to shifted input?No — a shift is a different input entirelyYes, largely — the same filter fires wherever the pattern appears
Right choice forUnstructured or already-flat features (tabular data, this MNIST demo)Anything with spatial or local structure — images, and (as a 1D filter) audio or sequences

This isn't "convolutional is strictly better" — a dense layer is cheaper and simpler when there is no spatial structure to exploit in the first place. It's the wrong tool specifically here, for the reason the permutation test just demonstrated.

09Getting it to learn

Why you cannot initialize the weights to zero

The classic from-scratch bug, and a genuinely interesting one. Set every weight in a layer to zero and every neuron computes exactly the same thing. Identical outputs mean identical gradients, so identical updates, so they stay identical forever. A 128-neuron layer permanently behaves as a single neuron.

This is the symmetry problem, and randomness is what breaks it. Neurons must start out different in order to become different.

But scale matters too. Too large and activations grow layer over layer until they overflow; too small and they shrink to nothing and the signal dies. Pick the spread so the scale is roughly preserved through each layer — for ReLU networks that is He initialization:

W ~ Normal( 0, √(2 ⁄ nin) )

For our first layer, nin = 784, giving a standard deviation of about 0.05. Biases can safely start at zero — the weights already broke the symmetry.

The training loop

  1. Take a mini-batch of examples
  2. forward → predictions
  3. loss → how wrong were they?
  4. backward → blame for every parameter
  5. Update → nudge each one downhill, then repeat

Three knobs you will actually turn. Learning rate is the step size and matters most — too small and training crawls, too large and it diverges (you saw both in section 6). Batch size is how many examples per update; 32–256 is normal, and the residual noise is useful because it shakes the model out of bad narrow minima. Epochs is how many full passes over the data — too few and it has not learned, too many and it overfits.

Parameters are the ~109k weights and biases the loop learns. Hyperparameters are learning rate, batch size, epochs, and layer widths — a handful of numbers you choose before training starts.

That loop in words is abstract — but you already watched it in the flesh, back in §1's curve-fitting widget, before you knew what a neuron or a matrix was. Everything §2 through §8 added since then was shape: what the function looks like inside. This section's He initialization is the last missing piece of how it learns — the starting condition that decides whether that loop even gets moving.

Overfitting and the three splits

Overfitting is when the model memorizes the training examples instead of learning the pattern. With 109,386 parameters and 60,000 images there is ample capacity to just remember answers — which gives perfect training accuracy and useless real-world accuracy.

SplitPurpose
Train (~80%)The model learns from it
Validation (~10%)You check on it while training, and tune hyperparameters against it
Test (~10%)Touched once, at the very end, for an honest number

If you tune hyperparameters against a set, you have indirectly fitted to it and its score is no longer honest. The test set is the one you do not get to iterate against.

Regularization: taxing large weights

One direct treatment for overfitting, alongside "get more data" and "shrink the model": add a penalty for large weights straight into the loss, so memorising the training set costs something. The build guide's part-1 companion derives it in full — the short version is L = Ldata + λΣw², and because that new term differentiates to 2λw, every update step becomes w ← w − η(∂Ldata/∂w + 2λw): the usual data-driven nudge, plus a constant small pull toward zero on every weight, every step.

Choosing the architecture

Start small, and only grow when the model underfits. If training accuracy itself is poor, the model is too small. If training accuracy is excellent but validation accuracy is poor, it is too large — or needs the regularization above. Those two symptoms point in opposite directions, and diagnosing which one you have is most of the skill. For MNIST, 784→128→64→10 gets you 97–98%; beyond that, architecture tweaks stop helping and you need convolutions.

Once you know it's underfitting, there are still several different knobs that all "add capacity" — they are not interchangeable, and picking the wrong one wastes a training run:

OptionWhat it buysCost / riskReach for it when
Widen a layerMore questions asked per layer (§3)Parameter count grows fastest here — §7's 4.4× jump from one wider layerThe features at that stage feel too coarse, not too shallow
Add depthMore composed, more abstract intermediate features (§5)Deeper stacks reintroduce §9's vanishing-gradient risk without careThe task needs higher-level features built from simpler ones, not just more of the same
Switch to convolutionReuses one filter across every position (§8) instead of paying for each position separatelyOnly pays off when the input actually has spatial/local structure to exploitYou're plateaued on an image (or image-like) task specifically, not tabular data
Train longer / lower the learning rateFree — no architecture change at allWon't fix a model that's genuinely too small, only a model that hasn't finished convergingLoss is still visibly decreasing when training stops

And the reverse diagnosis — overfitting — has its own equally non-interchangeable menu: L2 regularization (above) taxes large weights, more data directly shrinks the gap between memorizing and generalizing, and shrinking the model removes the spare capacity that made memorizing possible in the first place. All three treat the same symptom; none of them substitutes for correctly diagnosing which one you actually need.

10The implementation

Sixty lines, no autograd

No frameworks. Every gradient from section 6 appears explicitly. Section 6 gave those formulas for one example; below, every array has an extra leading dimension for the B examples in a batch, and a single matrix multiply computes and adds up all B examples' gradients at once — that sum is what makes a batch update one step rather than B of them.

import numpy as np

rng = np.random.default_rng(0)
SIZES = [784, 128, 64, 10]

# ---------- initialization ----------

def init_params(sizes):
    # He init: std = sqrt(2/n_in). Random breaks symmetry;
    # the scale keeps activations from exploding or vanishing.
    params = []
    for n_in, n_out in zip(sizes[:-1], sizes[1:]):
        W = rng.normal(0, np.sqrt(2.0 / n_in), (n_out, n_in))   # (out, in)
        b = np.zeros(n_out)                                    # zeros fine here
        params.append([W, b])
    return params

# ---------- forward ----------

def relu(z):
    return np.maximum(0, z)

def softmax(z):
    z = z - z.max(axis=1, keepdims=True)   # log-sum-exp trick: stops overflow,
    e = np.exp(z)                        # changes nothing mathematically
    return e / e.sum(axis=1, keepdims=True)

def forward(params, X):
    # X: (B, 784). Keep every intermediate — backward needs them.
    acts, pres = [X], []
    A, L = X, len(params)
    for i, (W, b) in enumerate(params):
        Z = A @ W.T + b                  # (B,in)(in,out) + (out,) broadcast
        pres.append(Z)
        A = softmax(Z) if i == L - 1 else relu(Z)
        acts.append(A)
    return acts, pres

def cross_entropy(Y_hat, y):
    B = y.shape[0]
    # Y_hat[np.arange(B), y] pairs row i with column y[i]: the predicted
    # probability of the true class, read out for all B examples at once.
    return -np.mean(np.log(Y_hat[np.arange(B), y] + 1e-12))   # +1e-12: never log(0)

# ---------- backward ----------

def backward(params, acts, pres, y):
    B, L = y.shape[0], len(params)
    Y = np.zeros_like(acts[-1])
    Y[np.arange(B), y] = 1                 # one-hot: 1 in the true-class column, 0 elsewhere, per row

    # softmax + cross-entropy collapse to exactly (predicted - actual)
    delta = (acts[-1] - Y) / B             # /B averages over the batch

    grads = [None] * L
    for i in range(L - 1, -1, -1):
        grads[i] = [delta.T @ acts[i],     # dL/dW = delta x^T, summed over the batch
                    delta.sum(axis=0)]     # dL/db = delta, summed over the batch
        if i > 0:
            delta = (delta @ params[i][0]) * (pres[i-1] > 0)
            #        ^ = W^T delta per example; delta is a row here, so it's W
            #          on the right instead of W^T on the left      ^ ReLU blocks blame where it was off

    return grads

# ---------- update ----------
# "stochastic" gradient descent: each step uses one random mini-batch,
# not the full dataset — the same downhill step from section 6.

def sgd(params, grads, lr):
    for (W, b), (dW, db) in zip(params, grads):
        W -= lr * dW
        b -= lr * db

# ---------- training loop ----------

def train(X, y, X_val, y_val, epochs=20, batch=64, lr=0.1):
    params = init_params(SIZES)
    n = X.shape[0]
    for ep in range(epochs):
        order = rng.permutation(n)       # reshuffle each epoch
        for s in range(0, n, batch):
            idx = order[s:s + batch]
            acts, pres = forward(params, X[idx])
            grads = backward(params, acts, pres, y[idx])
            sgd(params, grads, lr)

        val_probs = forward(params, X_val)[0][-1]   # [0]=acts list, [-1]=final softmax output
        acc = (val_probs.argmax(axis=1) == y_val).mean()
        print(f"epoch {ep+1:2d}   val acc {acc:.4f}")
    return params

Getting the data. MNIST pixels are 0–255 integers; divide by 255 so inputs sit in [0,1]. Unnormalized inputs are the second most common reason a from-scratch model refuses to learn.

11When it breaks

Bugs you will probably hit

SymptomLikely cause
Loss stuck at 2.303 (= ln 10)Nothing is learning — check the learning rate isn't ~0, and that you initialized randomly rather than to zeros
Loss goes NaNLearning rate too high, or you forgot the max-subtraction in softmax
Loss decreases painfully slowlyInputs not normalized to [0,1], or learning rate too small
Shape error in backwardYou transposed the wrong operand — recheck against the shape table in section 7
Trains, but accuracy stuck lowForgot to average the gradient over the batch (/B), so the effective learning rate scales with batch size
Train accuracy 100%, validation poorOverfitting — see section 9
Gradients plausible but training erraticYou used post-update weights in the backward pass; finish the whole backward pass before any update

The best debugging tool: gradient checking

Pick one weight, nudge it by ε = 10⁻⁵, recompute the loss, and compare (L(w+ε) − L(w−ε)) / 2ε against your analytic gradient. They should agree to about five decimal places. If they don't, your backward pass is wrong — and this tells you which layer is wrong.

Experiments worth running

Once it trains, change one thing at a time. This is where the understanding consolidates.

  1. Set all weights to zero. Accuracy sticks at ~10% — chance. Connect it to section 9.
  2. Remove the ReLUs. Accuracy drops to about 92%, what a plain linear classifier achieves — because that is precisely what the model has collapsed into.
  3. Set the learning rate to 10. Watch it diverge.
  4. Shrink to 784→8→10. Watch it underfit — training accuracy itself will be poor.
  5. Train on only 500 examples for 200 epochs. Training accuracy hits 100% while validation stalls. Overfitting, visible.
  6. Apply a fixed random permutation to every image's pixels. Accuracy unchanged.

Number six is the one most worth doing. It is genuinely surprising the first time.

12Summary

What to remember

The architecture

  • A neuron is a weighted question; a layer is many neurons; W is (outputs × inputs)
  • Hidden layers build intermediate features nobody designed
  • Without a nonlinearity between them, stacked layers collapse into one
  • The output layer gives logits; softmax turns them into probabilities

The learning

  • Loss measures wrongness; cross-entropy measures surprise at the true answer
  • Backprop assigns blame backwards using the chain rule, in one sweep because there is one loss and many parameters
  • A weight's blame is (error) × (activity)
  • Gradient descent nudges every weight downhill, over and over

The practice

  • Initialize randomly, at the right scale, or nothing learns
  • Normalize the inputs
  • Hold out validation and test data, and watch for validation loss turning up
  • Start small; grow only when the model underfits

The whole system is one pattern, repeated: transform, compare, adjust.
