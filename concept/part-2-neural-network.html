Neural networks are curve fitting

A neural network is a function with millions of adjustable numbers, fit to data the same way you'd fit a line through a scatter plot — just with a curvier function. This part builds that idea from the smallest possible case (two numbers, four points) up to a full, working network: the neuron, the layer, why depth needs a kink, softmax, the loss, the forward pass, the backward pass, the training loop, and a complete from-scratch implementation with no framework hiding anything.

01The mental model

A neural network is a function you fit to data

Strip away the vocabulary and a neural network is a function: numbers in, numbers out.

TaskInOut
Digit recognition784 pixel values10 class scores
House pricing12 property features1 price
Language modellinga sequence of tokensa score per possible next token

What makes it neural is that the function has millions of adjustable numbers inside it, and nobody sets them by hand — an optimization procedure finds them by looking at examples. So there are only ever two questions: what shape is the function, and how do we fit it. §02–§07 below answer the first; §08–§13 answer the second.

Three words carry the rest of this part:

  • Training — searching for the numbers inside the function that make its output match the data it's shown, by repeatedly measuring how wrong it is and nudging every number to be less wrong.
  • Inference — everything that happens after training: the numbers are frozen, you plug in a brand-new input, and evaluate the same equation once, forward, to get an answer.
  • Learning — the iterative part of training itself: not one fit, but a loop of small, equation-driven adjustments, repeated thousands of times.

This is curve fitting. If you've ever drawn a trend line through a scatter plot, you've done the easy version of exactly this already. Watch it happen on a function curvy enough to need more than a line, before any of the machinery behind it is explained:

02The smallest possible case

y = ax + b: training, by hand, on four points

Before any "neuron" vocabulary, do the whole loop — training and inference — on the simplest function there is: a line with two adjustable numbers, slope a and intercept b.

The data. Four points, generated (unknown to the model) by y = 2x + 1:

xy
13
25
37
49

The question training answers: what a and b make ŷ = ax + b match these points as closely as possible?

Step 1 — guess. a = 0, b = 0. (§12 covers why zero specifically becomes a problem once there's more than one path — for a single line it's harmless.)

Step 2 — measure how wrong. Mean squared error: L = (1/n) Σᵢ(ŷᵢ−yᵢ)². At a=0,b=0: predictions [0,0,0,0], errors [−3,−5,−7,−9], so L = (9+25+49+81)/4 = 41.

Step 3 — the gradient. Part 1's chain rule, on two inputs at once: ∂L/∂a = (2/n)Σᵢ(ŷᵢ−yᵢ)xᵢ, ∂L/∂b = (2/n)Σᵢ(ŷᵢ−yᵢ). Plugging in: ∂L/∂a = 0.5×(−70) = −35, ∂L/∂b = 0.5×(−24) = −12.

Step 4 — nudge downhill. Learning rate η=0.05: a ← 0−0.05×(−35) = 1.75, b ← 0−0.05×(−12) = 0.60.

Step 5 — repeat.

Inference. Freeze a≈2.00, b≈1.00. Given a brand-new x=10 — never seen during training — evaluate the line once: ŷ = 2×10+1 = 21. No searching, no loop: one forward evaluation. Everything below this section is this exact loop — guess, predict, measure, get the gradient, nudge, repeat — with a curvier function and vastly more numbers.

03The building block

The neuron is a tiny scoring machine

A line has one input. Real problems have many. A neuron takes several inputs, weights each by importance, sums them, adds a bias, and passes the result through a nonlinear function:

z = w₁x₁ + w₂x₂ + … + wₙxₙ + b   ⟶   a = f(z)

Recognize the first half: w·x + b is exactly Part 1 §04's dot product plus a constant — "how much does the input agree with what this neuron is looking for." A neuron is a dot product with a nonlinearity bolted on.

What weights mean

Weights are what the model learns. Everything the network knows lives in them.

  • Large positive — this input strongly pushes the output up
  • Near zero — this input is ignored
  • Large negative — this input pushes the output down

A useful reframing: the weights are the model. Save them and you have saved everything; lose them and you have nothing but architecture. The bias is the neuron's default answer before any evidence arrives — same role +c played for a line in §02.

04Layers

A layer is many neurons, and one matrix

One neuron gives one answer. We want many, so we run many neurons over the same input. Stack each neuron's weight vector as a row of a matrix and the whole layer becomes one multiplication:

h = f(Wx + b)

Each row of W is one neuron. One row = one question.

So a layer taking 3 inputs and producing 4 outputs needs 4 neurons (4 rows), each weighing 3 inputs (3 columns). With a batch: in practice you process many examples at once, stacked as rows — 64 images gives X at 64×784. Compute XWᵀ + b, giving 64×128 — the single bias vector adds to every row automatically (broadcasting).

Hidden layers and what they're for

A hidden layer is any layer between input and output — "hidden" only means its values are never directly observed. What makes them worth having is that they build intermediate representations:

raw pixels → edges → corners, curves → parts → whole objects

Each layer's output becomes the next layer's input, so later layers ask questions about earlier answers rather than raw data. Nobody designs these intermediate features; they emerge because features that reduce the loss get reinforced.

05Why it needs to be a network

Without a kink, depth is an illusion

The obvious next move: if one layer is limited, stack more. Check what happens with plain linear layers:

W₂(W₁x + b₁) + b₂ = (W₂W₁)x + (W₂b₁ + b₂) = W′x + b′

One layer. Not "weaker than two layers" — mathematically identical to one. Stack a thousand and it still collapses to one.

Sigmoid and tanh were used historically but saturate — their derivatives shrink toward zero for large inputs, stalling learning in deep stacks (§10). ReLU's derivative is exactly 1 on the positive side, so signal passes through undamaged.

FunctionDerivativeThe story
ReLU max(0,x)1 if x>0, else 0Cheapest kink. Can "die" at zero, but doesn't saturate on the positive side.
Sigmoid 1/(1+e⁻ˣ)σ(1−σ)Mostly retired: derivative maxes at 0.25, which kills deep networks.
GELU x·Φ(x)smoothReLU with the corner rounded. Standard in transformers (Part 5).
06The output end

Logits are not probabilities

The final layer has one neuron per class. Its raw output is a vector of unbounded real numbers called logits. Why we need softmax: a classifier needs output that behaves like a probability distribution — every entry in [0,1], summing to 1, and differentiable, so training can push a gradient through it. Softmax does both jobs:

softmax(z)ᵢ = eᶻⁱ ⁄ Σⱼ eᶻʲ

Trap: frameworks want logits passed to the loss, not probabilities — cross_entropy applies softmax internally in a numerically safer fused form. Applying softmax yourself and passing the result trains a worse model and never raises an error.

07Measuring wrong

Cross-entropy: scoring how wrong a belief was

The loss is one number saying how wrong a prediction was. For classification, use cross-entropy — the model's surprise at the correct answer:

L = −log( probability assigned to the true class )
08The forward pass

Push the input through, save everything

Forward means: push the input through the layers in order, computing each layer's output from the previous one's, saving every intermediate value along the way. You will need them for the backward pass — forgetting to save them is the most common from-scratch bug.

x → z₁=W₁x+b₁ → a₁=ReLU(z₁) → z₂=W₂a₁+b₂ → ŷ=softmax(z₂) → L=cross-entropy(ŷ,y)

Nothing here is new — it's §04's Wx+b, §05's ReLU, §06's softmax, and §07's loss, run once in sequence. Watch it happen on the real 784→128→64→10 model below, then walk it backward in §09.

09The backward pass

Backpropagation, properly

The problem. The loss is one number. The model has 109,386 knobs. For each knob: if I turn this up slightly, does the loss go up or down, and by how much? That list of answers is the gradient — really a list of blame.

Backward means: start at the loss and walk back through the layers, computing each one's share of the blame using the chain rule — Part 1's "rates feeding rates," now with thousands of nested functions instead of two.

Why backward and not forward? There is one loss and a hundred thousand parameters. Starting from the single output and walking back gets every gradient in one sweep. Starting from each parameter and walking forward would need one sweep per parameter. That asymmetry is the entire reason training is feasible.

Three facts make it concrete, for a layer y = Wx + b receiving blame δ from above:

∂L/∂W = δ xᵀ     ∂L/∂b = δ     ∂L/∂x = Wᵀ δ

Read the first in words: a weight's blame is (how wrong its output was) × (how active its input was). A weight can only be at fault if it was carrying signal. The third says blame flows back to the inputs through the same wires it came forward on. And softmax + cross-entropy together collapse beautifully: δ (at the output) = ŷ − y — "predicted minus actual," no logs or exponentials survive, despite both being full of them.

Worked by hand, on a network small enough to check

Two inputs → one hidden unit (ReLU) → one output, no biases. w₁=0.5, w₂=−0.3, w₃=0.8, input x=[2,1], target y=1: h = ReLU(0.5×2 + (−0.3)×1) = ReLU(0.7) = 0.7, ŷ = 0.8×0.7 = 0.56, L = (ŷ−y)² = 0.1936. Backward: ∂L/∂ŷ = 2(ŷ−y) = −0.88; ∂L/∂w₃ = −0.88×0.7 = −0.616; ∂L/∂h = −0.88×0.8 = −0.704, which (h>0, so ReLU's derivative is 1) passes straight through: ∂L/∂w₁ = −0.704×2 = −1.408, ∂L/∂w₂ = −0.704×1 = −0.704. Every one of those is the chain rule, applied once per edge, working backward.

10What goes wrong

Vanishing gradients, and the fix

Deep stacks multiply many local derivatives together via the chain rule. Sigmoid's derivative never exceeds 0.25 — stack ten sigmoid layers and the gradient shrinks by up to 0.25¹⁰ ≈ 10⁻⁶ before it reaches the first layer, which then barely updates at all. ReLU's derivative is exactly 1 wherever it's active, so the activation itself adds no extra shrinkage — what's left to shrink the signal is only the weight matrices it passes through, which rarely preserve magnitude exactly. A residual connection, x + F(x), adds a guaranteed +1 to the derivative on top of that, regardless of what F computes — a bypass road the gradient can always travel.

11The training loop

Gradient descent: the nudge, made precise

Part 1 built the gradient — the direction of steepest increase. Training wants the loss to go down:

w ← w − η ∂L/∂w
  1. Take a mini-batch of examples
  2. forward → predictions (§08)
  3. loss → how wrong were they? (§07)
  4. backward → blame for every parameter (§09)
  5. update → nudge each one downhill, then repeat

This is §02's four-point line-fitting loop, unchanged in structure, just with a curvier function and orders of magnitude more numbers.

Learning rate is the step size and matters most. Batch size — how many examples per update; 32–256 is typical, and the residual noise is useful, shaking the model out of bad narrow minima. Epochs — full passes over the data; too few and it hasn't learned, too many and it overfits (§13). Parameters are what the loop learns; hyperparameters — learning rate, batch size, epochs, widths — are what you choose beforehand.

12Getting it to learn

Why you cannot initialize the weights to zero

Set every weight in a layer to zero and every neuron computes exactly the same thing. Identical outputs mean identical gradients, so identical updates, so they stay identical forever. This is the symmetry problem, and randomness is what breaks it.

Scale matters too. Pick the spread so activations neither explode nor vanish through each layer — for ReLU networks, that's He initialization: W ~ Normal(0, √(2/n_in)). For a 784-input layer that's a standard deviation of about 0.05. Biases can safely start at zero — the weights already broke the symmetry.

13When it goes wrong

Overfitting and capacity

Overfitting is when the model memorizes the training examples instead of learning the pattern — perfect training accuracy, useless real-world accuracy. The signature: training loss still falling while validation loss turns back up.

SplitPurpose
Train (~80%)The model learns from it
Validation (~10%)Checked during training; hyperparameters get tuned against it
Test (~10%)Touched once, at the very end, for an honest number

Regularization taxes large weights directly in the loss: L = L_data + λΣw². If training accuracy itself is poor, the model is too small; if training accuracy is excellent but validation is poor, it's too large — add regularization, more data, or shrink the model.

Template · every neural network, every time
The eight steps that don't change

Everything above is one instance of this. Swap the architecture, the data, or the loss, and these eight steps are still exactly what runs:

  1. Define the architecture — how many layers, how many neurons per layer, which activation (§03–§05)
  2. Initialize the weights — small random values, never all zero (§12)
  3. Forward pass — push one input through, saving every intermediate value (§08)
  4. Compute the loss — compare the prediction to the target (§07)
  5. Backward pass — the chain rule, run backward through every layer, assigning blame to every weight (§09)
  6. Update — nudge each weight opposite its gradient, scaled by the learning rate η (§11)
  7. Repeat steps 3–6 over many batches and epochs, checking validation loss, until it stops improving (§13)
  8. Inference — freeze the weights, run step 3 once on data never seen during training. No loss, no backward pass (§01)

§14 through §15 are this exact template, four different times: same eight steps, a different shape swapped in for step 1.

15The implementation

A neural network from scratch — no PyTorch

Every gradient formula from §09 appears explicitly below. Every array has a leading batch dimension B, and a single matrix multiply computes and sums all B examples' gradients at once.

import numpy as np

rng = np.random.default_rng(0)
SIZES = [784, 128, 64, 10]

# ---------- initialization (§12) ----------

def init_params(sizes):
    # He init: std = sqrt(2/n_in). Random breaks symmetry;
    # the scale keeps activations from exploding or vanishing.
    params = []
    for n_in, n_out in zip(sizes[:-1], sizes[1:]):
        W = rng.normal(0, np.sqrt(2.0 / n_in), (n_out, n_in))
        b = np.zeros(n_out)
        params.append([W, b])
    return params

# ---------- forward (§08) ----------

def relu(z):
    return np.maximum(0, z)

def softmax(z):
    z = z - z.max(axis=1, keepdims=True)   # log-sum-exp trick (§06)
    e = np.exp(z)
    return e / e.sum(axis=1, keepdims=True)

def forward(params, X):
    acts, pres = [X], []
    A, L = X, len(params)
    for i, (W, b) in enumerate(params):
        Z = A @ W.T + b                  # (§04)
        pres.append(Z)
        A = softmax(Z) if i == L - 1 else relu(Z)
        acts.append(A)
    return acts, pres

def cross_entropy(Y_hat, y):                                # (§07)
    B = y.shape[0]
    return -np.mean(np.log(Y_hat[np.arange(B), y] + 1e-12))

# ---------- backward (§09) ----------

def backward(params, acts, pres, y):
    B, L = y.shape[0], len(params)
    Y = np.zeros_like(acts[-1])
    Y[np.arange(B), y] = 1

    delta = (acts[-1] - Y) / B      # softmax+CE collapse to (predicted-actual)

    grads = [None] * L
    for i in range(L - 1, -1, -1):
        grads[i] = [delta.T @ acts[i], delta.sum(axis=0)]
        if i > 0:
            delta = (delta @ params[i][0]) * (pres[i-1] > 0)  # ReLU gate
    return grads

# ---------- update + loop (§11) ----------

def sgd(params, grads, lr):
    for (W, b), (dW, db) in zip(params, grads):
        W -= lr * dW
        b -= lr * db

def train(X, y, X_val, y_val, epochs=20, batch=64, lr=0.1):
    params = init_params(SIZES)
    n = X.shape[0]
    for ep in range(epochs):
        order = rng.permutation(n)
        for s in range(0, n, batch):
            idx = order[s:s + batch]
            acts, pres = forward(params, X[idx])
            grads = backward(params, acts, pres, y[idx])
            sgd(params, grads, lr)
        val_probs = forward(params, X_val)[0][-1]
        acc = (val_probs.argmax(axis=1) == y_val).mean()
        print(f"epoch {ep+1:2d}   val acc {acc:.4f}")
    return params

17Onward

What comes next

A neuron is a weighted question; a layer is many neurons; W is (outputs × inputs). Without a kink between layers, depth collapses to one linear function. Softmax turns logits into probabilities; cross-entropy measures surprise at the truth. Backprop assigns blame backward via the chain rule, in one sweep. Gradient descent nudges every weight downhill — the exact same loop as fitting y=ax+b in §02, just with a curvier function and many more numbers.

Every gradient above was computed by hand, in raw NumPy — necessary once, so you could see exactly where every formula comes from. Part 3 shows you the tool a working engineer actually reaches for, so you never have to write backward() by hand again. Part 4 then points this same machinery at four more problems.
