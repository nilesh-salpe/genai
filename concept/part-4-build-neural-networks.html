Build Neural Networks: four problems

Nothing new gets built on this page — every formula is from Part 3. What changes is the problem: a decision boundary that isn't a line, an image instead of a table of numbers, and two flavors of "which of these matters right now" that quietly rehearse Part 5's attention before it has a name. Each example follows the same template: the problem, the outcome, the example itself, why a plain formula can't do it, the solution in brief, and the runnable notebook behind it.

01Not a line

A spiral, and why one straight cut can't solve it

What is the problemTwo classes of points, arranged as interleaved spirals — no straight line separates them, no matter how it's angled.
What is the outcomeA trained network that draws a curved decision boundary — both spiral arms correctly separated, at an accuracy a straight-line classifier structurally cannot reach.
The exampleA synthetic 2D dataset: points sampled along two spiral arms, colored by class. Purely visual, so the decision boundary can be watched directly.
Why a neural network is neededA network with a kink (Part 3 §05) can bend its decision boundary to match; a purely linear model — logistic regression, or a network with no activation — provably tops out far below what a kinked network reaches here, no matter how it's trained.
The solution, brieflyA small ReLU network, trained with Part 3's exact backprop and softmax + cross-entropy. Watch the shaded decision region fold itself around both spiral arms as training proceeds.
Notebook01_mlp_spiral_classifier.ipynb — the full version, gradient-checked against numerical differentiation.
02Not a bag of pixels

Why images want a filter, not a flatten

What is the problemA vertical stripe and a horizontal stripe are the same pattern, just rotated — obvious to an eye. Flatten an image first, and that's gone: position (0,0) and position (1,0) are adjacent in the image but arbitrary strangers in the flattened vector.
What is the outcomeA single 3×3 filter that learns, from data alone, to detect one orientation of stripe — and generalizes to any position in the image, because the same 9 numbers are reused everywhere.
The exampleSmall synthetic images containing either vertical or horizontal stripes — a minimal case for a mechanism that scales to real images in the notebook.
Why a neural network is neededA dense layer can only solve this by memorizing pixel positions per pattern — one full set of weights per position that pattern might appear at. A convolution keeps the 2D grid: one small filter slides over every position, computing the same dot product each time, so "detect an edge" is learned once and applies everywhere.
The solution, brieflyOne 3×3 kernel, trained end-to-end. Watch the filter's own 9 numbers converge into a stripe-shaped pattern — strong along one direction, weak along the other.
Notebook02_cnn_digit_classifier.ipynb — full im2col conv forward/backward, max-pool, dense, on real 8×8 digit images, reaching 90% test accuracy.
03Which one matters

Retrieval by similarity: a preview of attention

What is the problemImagine a lookup table where you don't know which row your answer is in — you only know what its label should match. A plain array lookup needs a known position; this needs a comparison against every label.
What is the outcomeA mechanism that retrieves the value paired with the best-matching key — by content, not position — and blends smoothly when more than one key is a partial match.
The exampleThree stored (key, value) pairs and one query, all 2D vectors so they can be dragged and watched directly.
Why a neural network is neededThis is a genuinely new operation, not a bigger version of §01–§02's machinery: score the query against every key with a dot product (Part 1 §04), softmax the scores into weights (Part 3 §06), then return the weighted average of the values — not the single best match, a blend weighted by how well each key matched.
The solution, brieflyDrag the query near a key and its weight climbs toward 1 while the others fall toward 0. Drag it equidistant from two keys and the output blends them.
Notebook03_mini_attention_retrieval.ipynb — full embeddings, Wq/Wk/Wv, output projection, gradient-checked exactly.
04Not allowed to peek

Predicting the next character, without seeing the future

What is the problemPredicting what comes next is easy if you're allowed to peek ahead — you'd just be copying the answer. A model generating text one character at a time never gets that peek.
What is the outcomeA model that predicts the next character at every position simultaneously, using only the characters up to and including that position — the actual training setup for every autoregressive language model.
The exampleA short alternating series, "ababab...". Task: at every position, predict the next character using only what's been seen so far.
Why a neural network is neededThis reuses §03's retrieval-by-similarity but runs it at every position at once, under a causal mask: position i is blocked from attending to any position j > i — otherwise the "prediction" is just copying an answer it was handed.
The solution, brieflyThe greyed-out characters are masked — invisible to the current position's prediction, no matter how useful they'd be. Advance and watch the visible window grow by exactly one every step.
Notebook04_causal_series_predictor.ipynb — gradient-checked, full causal attention.
05Onward

The spiral and the filter were Part 3's machinery on new shapes of data. The retrieval example and the causal mask were rehearsals — the exact arithmetic and the exact rule Part 5 is about to name properly, derive from scratch, and assemble into the mechanism every current LLM runs.
