The maths under the maths

Before any neural network, a warm-up in the plain maths every later part leans on: functions, sums, vectors and matrices, exponentials and logarithms, derivatives and the chain rule, and randomness. None of it mentions a neural network. All of it gets used by the end of Part 1. If you already have a linear algebra, calculus, and probability course behind you, skim for notation and move on — Part 1 starts from here, not from zero.

00How to read this

What this page is for

Everything Part 1 needs and doesn't build itself: rearranging a formula, vectors and matrices, exponentials and logarithms, what a derivative is, the chain rule, and two facts about randomness. This page builds each one from nothing but arithmetic, with no neural network in sight. Part 1 then puts all of it straight to work building softmax, cross-entropy, and attention.

Assumed here: adding, multiplying, and dividing. Nothing else.

01Inputs and outputs

A function is a machine, not a mystery

The problem. We keep writing things like f(x), softmax(z), loss(ŷ, y) — all the same shape: something goes in, one rule is applied, something comes out.

A function is a machine with an input slot and an output slot, and a fixed rule connecting them. f(x) = x + 5 is "add 5" — feed it 3, get 8; feed it −5, get 0. The letter x is a placeholder for whatever goes in this time; it is not a fixed number. f(x) = 2x is "double it." f(x) = x² is "multiply it by itself." None of this is new to you — it is exactly what y = mx + c already was in school algebra, just written with the input and the rule made explicit instead of implicit.

Two habits carry all the way through this course:

  • Functions can take more than one input. f(x, y) = x·y is a machine with two slots. A neural network's loss function takes millions of inputs (the weights) and one more (the data) and produces a single number.
  • The output of one function can be the input to another. f(g(x)) means: run x through g first, then feed that result into f. A whole neural network is nothing but functions plugged into functions, layer after layer — this one habit, repeated.

Rearranging. y = mx + c solved for x is x = (y − c) / m — same fact about the same three quantities, read in a different direction. Whenever a later derivation "solves for" something, this is the entire move: apply the same operation to both sides until the letter you want is alone.

02Adding many things

Σ is a for-loop, not a new operation

The problem. "Add up these five numbers" is easy to say and clumsy to write five times. Σ (capital sigma) is shorthand for exactly that — nothing more.

Σᵢ xᵢ  =  x₁ + x₂ + x₃ + ⋯ + xₙ

Read it as: "for every i from 1 to n, take xᵢ, and add it to a running total." If x = [3, 1, 4, 1, 5], then Σᵢ xᵢ = 3+1+4+1+5 = 14. It appears with a rule attached almost as often as alone — Σᵢ xᵢ² means "square each one first, then add," giving 9+1+16+1+25 = 52. Every dot product, every layer of a network, and every loss function in this course is a Σ wearing different clothes: a rule applied to each of many things, then totalled into one number.

03Bundling numbers

A vector is a filled-in form

The problem. Computers only do arithmetic, but we want to work with people, photos, and sentences. So step one is always: turn the thing into numbers — and one number is rarely enough. A person is a collection of measurements. A photo is millions of brightness values. A word is a few hundred numbers encoding its meaning.

The picture. A vector is a filled-in form — drop the labels, fix the order, and [34, 52000, 8] is a person (age, income, years of school). There is a second reading that matters later: three numbers are also coordinates, a location in space. So every data point is simultaneously a form and a point. That duality is what lets you ask geometric questions about things that are not obviously geometric at all — which is exactly what the next section does.

04The core operation

The dot product measures agreement

The problem. I have a list of things I care about and a list of what is present. How much do they agree?

A spam filter cares about: the word "free" (+2), sender in contacts (−3), exclamation marks (+1). An email arrives with "free" (1), sender unknown (0), four marks (4):

(2)(1) + (−3)(0) + (1)(4) = 6

Why multiply the pairs rather than add them? Because we want a score that is large only when both are large and pointing the same way. Care a lot but the feature is absent? Contributes nothing. Care negatively and the feature is present? Pulls the score down. Multiplication is the operation encoding "both of these must hold for it to count."

w · x = Σᵢ wᵢxᵢ     two vectors in, one number out

The geometric reading. Define length by Pythagoras, ‖a‖ = √(Σaᵢ²). Then:

a · b = ‖a‖ ‖b‖ cos θ

You can see why in 2D: rotate the axes so a points along x. Then a = (‖a‖, 0) and b = (‖b‖cos θ, ‖b‖sin θ), and the dot product is ‖a‖‖b‖cos θ + 0. Rotating does not change dot products, so this holds generally.

05Doing it in bulk

Matrices, and the shape rule that derives itself

One dot product gives one verdict; sometimes you want several at once. Three questions means three "what I care about" lists, stacked as rows of a grid. That grid is a matrix.

Each row of a matrix is one question. Multiplying by the matrix asks every question at once.

(Wx)ᵢ = Σⱼ Wᵢⱼ xⱼ

Matrix multiplication is not a new operation — it is bookkeeping for many dot products at once, which is also why GPUs matter: every row's dot product is independent of every other row's, so they can all run at the same time.

The shape rule. People memorise (m×n)(n×p) = (m×p). You do not need to. Every output entry is a dot product between a row of the first and a column of the second — and a dot product needs both lists the same length, so the inner dimensions must match. You get one output per (row, column) pair, so the result is (rows of first) × (columns of second).

Two more operations, both used later. Transpose Aᵀ flips the grid across its diagonal. Outer product goes the opposite way from a dot product — two vectors give a whole matrix, a column (2×1) times a row (1×3) giving 2×3. Elementwise product ⊙ multiplies matching entries instead of summing them.

The constant term. y = mx + c needed that +c — without it, an input of zero is forced to output zero, and the line's tipping point is stuck at the origin. The vector/matrix version needs the same fix: Wx + b, a constant vector b added after the multiplication, for exactly the same reason.

Box A · refresher
Exponentials and logarithms

An exponential answers "what do I get from multiplying e by itself this many times?" — e² = e·e ≈ 7.39, and the curve fills in every value in between, even fractional exponents (e0.5 ≈ 1.65) and negative ones (e−1 ≈ 0.37). A logarithm asks the reverse question — "e to what power gives me this number?" — so log(7.39) ≈ 2, because e² ≈ 7.39. They undo each other, the same way squaring and square-rooting do.

PropertyWhy it will matter
ex > 0 for every real xA sum of positive numbers can be turned into proportions
strictly increasingBigger input always means bigger output — nothing gets reordered
ea·eb = ea+b, so ea/eb = ea−bShifting every input by the same amount changes nothing about the ratios
log(ab) = log a + log bThe defining property. Turns multiplication into addition
log 1 = 0Zero on the log scale means "unchanged"
log x → −∞ as x → 0Getting close to zero costs more and more, without bound
d/dx log x = 1/xIts slope is just "one over the input" — a fact §7 below will use

Log turns multiplication into addition. Part 1 leans on that single fact three separate times.

07Rates of change

The derivative: how fast, right here

The problem. A function's output changes as its input changes — but not always at the same rate. f(x) = x² barely moves near x = 0 and rockets upward near x = 10. "The derivative" is just a name for the rate of change at one specific point — how steep the graph is, right there.

The picture. Pick two points on the curve and draw a straight line through them — a secant line. Its slope is "rise over run": how much f went up, divided by how far x moved.

slope  =  (f(a+h) − f(a)) / h

Now shrink the gap h toward zero. The two points slide together, and the secant line — the line through two nearby points — settles onto the line that just grazes the curve at one point: the tangent line. Its slope is the derivative of f at a, written f′(a) or df/dx.

You never need to take that limit by hand again after today — there is a short list of rules that do it for every function you will meet.

08Two rules, everything downstream

The power rule, and the chain rule

The power rule. For f(x) = xⁿ, the derivative is f′(x) = n·xn−1 — bring the exponent down as a multiplier, then subtract one from it. Check it against the widget above: f(x) = x² has n = 2, so f′(x) = 2x — exactly the slope the tangent line converged to.

FunctionDerivativeRead as
f(x) = xf′(x) = 1A straight 45° line — constant slope
f(x) = x²f′(x) = 2xSteeper the further from zero, either direction
f(x) = c  (a constant)f′(x) = 0Flat — a number that doesn't move has no rate of change
f(x) = c·g(x)f′(x) = c·g′(x)A constant multiplier just scales the slope

The problem the chain rule solves. Real functions are rarely that clean — they are functions of functions. h(x) = (2x + 1)² is "double x, add 1, then square the result" — an inner function g(x) = 2x+1 feeding an outer one f(u) = u². What is the rate of change of the whole chain?

Nudge x a little. That nudges g(x) by a rate of g′(x). That nudge in g(x) then nudges f by a further rate of f′(g(x)). Two multipliers applied back to back multiply:

d/dx f(g(x))  =  f′(g(x)) · g′(x)

The chain rule is not a trick — it is bookkeeping for "one rate feeding into another," and it is the only idea behind backpropagation (Part 1 §7): a network is nothing but functions nested inside functions, exactly like h above, just with thousands of layers of nesting instead of two.

09Many inputs

The gradient: one derivative per input

The problem. Every derivative so far was for a function of one number. But §1 already said the real target is a loss function of millions of inputs — one per weight, plus the data. "How does the output change?" now needs an answer per input, not one answer overall.

The picture. Freeze every input except one, and ask the ordinary single-variable question for just that one. That is a partial derivative, written ∂f/∂x — the exact same derivative from §7, just applied to one slot of a multi-input function while every other slot sits still, treated as a constant.

Worked example. f(x, y) = x²y. Holding y fixed, the power rule on x gives ∂f/∂x = 2xy. Holding x fixed, x² is just a constant multiplier on y, so ∂f/∂y = x². At (x, y) = (2, 3): ∂f/∂x = 2(2)(3) = 12, ∂f/∂y = 2² = 4.

Collect one partial derivative per input into a vector, in order, and you have the gradient: ∇f = (∂f/∂x, ∂f/∂y) = (12, 4) at that point — a list where entry i answers "if I nudge only input i, how fast does the output move?"

Why "steepest increase," exactly. Recall the dot product from §4: nudging the input by a small step vector d changes the output by approximately ∇f · d. A dot product is largest when the two vectors point the same way — so the step d that increases f the most is the one pointing the same direction as ∇f itself. That is the whole reason the gradient is "the direction of steepest increase," not an assertion to memorise.

Nothing above changes when the count goes from 2 inputs to 2 million: Part 1 collects one partial derivative per weight into a single vector, calls it the gradient of the loss, and everything built here — what it means, why it points uphill — carries over exactly.

10Randomness

Expected value: the honest average of "it depends"

The problem. A quantity that comes out differently each time — a die roll, tomorrow's temperature, a model's confidence — is a random variable. It doesn't have one value; it has a list of possible values, each with a probability. What single number best summarises it?

The expected value, written E[X], is that summary: multiply each possible outcome by its probability, and add. It is a weighted average — outcomes that happen more often pull the summary toward themselves.

E[X]  =  Σᵢ pᵢ xᵢ

Roll a fair six-sided die: each face has probability 1/6, so E[X] = (1+2+3+4+5+6)/6 = 3.5 — a number the die can never actually show, and that is fine. It is the long-run balance point, not a prediction of any single roll.

Variance is built from the same expectation machinery: it is E[(X − E[X])²] — the expected squared distance from the balance point. Its square root, the standard deviation, is the typical size of a deviation. Spread out outcomes far from the mean, and variance grows; cluster them near it, and variance shrinks toward zero.

Fact 1 — for independent quantities, variances add. Note it is variances that add, not standard deviations. So adding up n independent things each with variance 1 gives variance n, and typical size √n — not n.

Var(X + Y) = Var(X) + Var(Y)

Why √n and not n? Because the terms have random signs and partially cancel.

Fact 2 — for independent quantities with mean zero, variances multiply: Var(XY) = Var(X)·Var(Y). With zero means, Var(XY) = E[X²Y²] — the same weighted average as above, just of X²Y² instead of X — and independence splits that into E[X²]E[Y²].

Hold on to both facts — independent things summed have spread √n, and independent zero-mean things multiplied have multiplied variance — Part 1 reaches for exactly this reasoning twice, in two places that look nothing alike until you notice they're both "summing n independent products, so the spread grows like √n, so divide by √n to undo it."

11Onward

What Part 1 assumes from here

Everything above was built without a single neural network: a function as an input/output machine, Σ as an addition loop, vectors and matrices as bundles of numbers with a well-defined way to multiply, exponentials and logarithms undoing each other, the derivative as a limit of secant slopes with the power and chain rules to compute it without limits, the gradient as one partial derivative per input, and E[X]/variance as a probability-weighted average and its spread. Part 1 uses every one of these — vectors and dot products to represent data and score agreement, matrices to do many of those at once, exp/log inside softmax and cross-entropy, the chain rule and the gradient as the entire content of backpropagation, and the two variance facts to derive attention's √dk scaling and weight initialization. Nothing there will be new machinery; it will be these tools, pointed at a new problem.
