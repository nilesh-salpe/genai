Attention, derived

Part 3's retrieval widget — a query, some keys, a softmax-weighted blend of values — was already attention's arithmetic. This page gives it the name, the matrices, the scaling factor, multiple heads, the rule against peeking, and a way to tell position apart from content: everything "Attention Is All You Need" (Vaswani et al., 2017) actually introduces.

01From one query to every position

Q, K, V: the same retrieval, run for the whole sequence at once

Part 3's query, key, and value were hand-picked vectors. In a real model they're computed from each token's embedding, by three learned matrices: Q = XWQ, K = XWK, V = XWV, where X stacks every token's embedding as a row. Every token gets its own query ("what am I looking for"), its own key ("what do I contain, as advertised to others"), and its own value ("what I'll actually contribute if attended to") — three different linear projections of the same embedding, for three different jobs.

Attention(Q,K,V) = softmax( QKᵀ / √d_k ) V

Read left to right: QKᵀ scores every query against every key at once (a matrix of dot products — Part 1 §4's agreement measure, done n² times in one multiply); divide by √d_k (§2 below); softmax turns each row into a probability distribution over positions; multiplying by V takes the weighted average of values that Part 3 already built by hand.

02The scaling factor

Why √d_k, and not "for numerical stability"

Suppose q and k's entries are roughly independent, mean 0, variance 1 — what initialization and layer norm arrange. Their dot product sums d_k independent products; by Part 1 §10's fact, variances add, so the dot product's variance is d_k and its typical size is √d_k. As d_k grows, raw scores grow with it — and Part 2 §2 showed a confident softmax has almost no gradient. Dividing by √d_k undoes exactly this growth, keeping scores in the range where softmax still responds to changes.

03Multiple questions at once

Multi-head attention: several attention patterns in parallel

One attention head can only ask one kind of question per position. The paper's fix: split Q, K, V into h smaller pieces (heads), run the identical attention formula on each piece independently and in parallel, then concatenate the results back together and project once more. Each head is free to specialize — one might track nearby words, another long-range subject-verb agreement — because nothing forces them to learn the same pattern.

MultiHead(Q,K,V) = Concat(head₁, …, head_h) Wᴼ    headᵢ = Attention(QWᵢQ, KWᵢK, VWᵢV)
04No peeking

The causal mask, formalized

Part 3 §4 showed the rule; here is the mechanism. Before softmax, set every score where key position j > i to −∞. Since e⁻∞ = 0, those positions get exactly zero weight after softmax — not "very small," exactly zero — while every row still sums to 1, because the mask only redistributes attention among the allowed positions rather than shrinking the total. In code this is a large negative number (like −10⁹) added to the score matrix before softmax, since a literal infinity would produce NaNs.

05Telling position from content

Positional encoding: attention alone can't tell order

Every dot product above depends only on the vectors involved, not on where they sit in the sequence — shuffle every token and every Q·K score shuffles identically, unchanged. Without a fix, "dog bites man" and "man bites dog" would attend identically. The paper's fix: add a fixed pattern to each token's embedding before attention runs, built from sines and cosines at different frequencies per dimension:

PE(pos, 2i) = sin(pos / 10000^(2i/d))    PE(pos, 2i+1) = cos(pos / 10000^(2i/d))
06Onward

What Part 5 assembles

Every piece "Attention Is All You Need" introduces is now built: Q/K/V from learned projections, the √d_k scaling and why, multiple heads in parallel, the causal mask, and positional encoding. What's left is architecture — wrapping attention in residual connections and layer norm, pairing it with a feed-forward network, stacking that block many times, and (in the paper's original design) splitting the stack into an encoder and a decoder that talk to each other.
