A GPT-style model is a decoder-only stack — no separate encoder, because there's no second sequence to consult; the model just keeps predicting its own next token from everything generated so far.

02Tokenization

Turning text into integers, as simply as possible

A network needs numbers, not characters (Part 1 §3). The simplest tokenizer: collect every unique character in the training text, assign each one an integer. "abc" with vocabulary {a:0, b:1, c:2} becomes [0, 1, 2]. Real models use larger sub-word vocabularies for efficiency, but the idea — a fixed lookup table, text in, integers out — doesn't change.

03The model, assembled

Embed → blocks → project → probabilities

Each token id becomes a learned vector (an embedding); Part 4 §5's positional encoding is added on top. That passes through N decoder blocks (Part 5 §1) — causal self-attention, then feed-forward, each behind its own residual connection. A final linear layer projects down to one score per vocabulary character — logits — and softmax turns those into probabilities over "what comes next."

tokens → embed + position → N × block → linear → softmax → P(next token)
04Training it

The same five calls, run on real text

Below, the simplest possible next-character predictor — a lookup table of logits, one row per "current character" — stands in for the full block stack, so the training loop itself is fully visible without a full Transformer's backward pass hidden inside it. Forward: read off logits for the current character, softmax them. Loss: cross-entropy against the real next character (Part 2 §3). Backward: gradient of that loss with respect to every logit. Update: nudge them (Part 2 §4). Repeat, on every character of the training text, every epoch.

05Generating

The autoregressive loop

Predict a probability distribution for the next character, sample one, append it to the context, and predict again — each new character becomes part of the input for the very next prediction. This loop is why generation is sequential: token n+1 generally can't be produced until token n exists.

06Onward

What's left is scale, not new ideas

Swap the lookup-table stand-in for a real stack of Part 5's blocks, widen the embeddings, add more blocks, train on vastly more text for vastly longer — and the loop above, unchanged in kind, is how every current large language model is trained.
