01Classification, applied

A spiral only a nonlinearity can untangle

Picture three tangled spiral arms on a page, each a different color. No matter how you angle a single straight line, it can separate at most a sliver of one arm from the rest — the arms wind around each other, so any straight cut you draw is wrong somewhere along its length. Part one §04 argues that without a kink, stacking layers collapses to one big linear function no matter how deep you go — a straight line (or plane) can never separate points that spiral around each other. This is that argument made concrete: a 2 → 32 → 32 → 3 ReLU network, trained with the exact backprop formulas from part two §06 (δ, ∂L/∂W = δxᵀ, ∂L/∂x = Wᵀδ) and the softmax + cross-entropy from part one §05–06, learning to separate three interleaved spiral arms that no straight line ever could.

02Why convolutions exist

One learned filter, doing what a dense layer can't

A vertical stripe and a horizontal stripe are the same pattern, just rotated — obvious to an eye, because an eye looks at the whole 2D shape at once. A model that flattened the image first never got that view; it sees 64 numbers in a row, with no notion that some of them used to be stacked in a column. Part two §08 ("The dense layer never sees a picture") argues that flattening an image throws away which pixels were neighbours, and that a convolution fixes this by sliding one small set of weights over every position instead. Here's that filter actually learning: a single 3×3 kernel, trained to tell vertical stripes from horizontal ones — something a dense layer can only do by memorising pixel positions, and a conv filter does by learning one small, reusable pattern.

03Attention, applied

Retrieval by content, not position

Imagine a lookup table where you don't know which row your answer is in — you only know what its label should match. A plain array lookup needs a position; this needs a comparison against every label to find the right one, wherever it happens to sit. That is retrieval by content, and it is the entire idea attention exists to do. Part one §11 derives attention in five steps: score relevance with a dot product, separate "what I seek" (query) from "what I am" (key) with two projections, turn scores into weights with softmax, retrieve with a value projection and a weighted sum, and divide by √d_k so the softmax doesn't saturate. Below is exactly that, solving the simplest task attention is built for: given a few key–value pairs and a query key, find the pair whose key matches and return its value — something a network has to learn to do by content, since the matching pair can be anywhere in the sequence.

04Prediction, at every step

The next symbol, predicted causally

Predicting what comes next is easy if you're allowed to peek ahead — you'd just be copying the answer. A model generating text one word at a time never gets that peek: every single prediction has to come from strictly what came before it, nothing more. Part one §11 also derives causal masking: a position can only attend to itself and whatever came before it, never the future — otherwise "predict the next token" would just mean copying it. This is the hardest of the four, because it reuses example three's Q/K/V attention but runs it at every position at once, under that mask — the actual loop a language model runs: given tokens[0..i], predict token[i+1], for every i simultaneously.

Both of these examples could, in principle, be solved a cheaper way — look back a fixed number of positions instead of comparing against all of them. Part one §04's "distance problem" is exactly why that cheaper option loses:
