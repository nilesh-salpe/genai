The Transformer, derived and assembled

Part 4's retrieval widget — a query, some keys, a softmax-weighted blend of values — was already attention's arithmetic. This page gives it the name, the matrices, the scaling factor, multiple heads, the rule against peeking, and a way to tell position apart from content — then wraps all of it into a stackable block, explains why the original paper split that block into two cooperating stacks, and covers the last mile from a trained model's raw output to an actual chosen word. Everything "Attention Is All You Need" (Vaswani et al., 2017) introduces, in one place.

00The paper

Why this became the field's reference point

"Attention Is All You Need" wasn't the first encoder-decoder architecture — RNN- and CNN-based sequence-to-sequence models, connected by an earlier, more limited form of attention, already existed. What was new was the paper's central claim: dispense with recurrence and convolution entirely, and build a sequence model out of attention alone.

The problem it addressed. Recurrent models process a sequence strictly one step at a time — token t waits for token t−1 to finish. That serializes training and makes long-range information fragile: a signal from token 3 has to survive being carried, step by step, all the way to token 300, and tends to fade.

RNN-based seq2seqTransformer
Processing orderStrictly sequentialEvery position processed in parallel
Long-range infoCarried step by step; tends to fadeAny two positions are one dot product apart
Training cost (reported)~2 months for a comparable task, pre-20173.5 days, 8 GPUs
Cost that grows with lengthLinear, but sequentialQuadratic (§10) — the trade being made

Not a marginal result: 28.4 BLEU on WMT 2014 English→German, 41.8 BLEU on English→French — a new state of the art. A genuine quality jump and a training-time collapse from months to days is the kind of result a field reorganizes around.

01Why attention, specifically

The problem a fixed-position lookup can't solve

Take: "The animal didn't cross the street because it was too tired." What does "it" refer to? To represent "it" correctly, a model needs "animal" — six words back. In a different sentence, "it" would look somewhere else entirely, so the lookup cannot be hardcoded to a fixed distance; it has to be decided per-sentence, per-word, based on content.

Fixed window (classical NLP)Attention
Cost per positionO(window size) — cheap, constantO(n) — scales with sequence length
Reaches the whole sequence?No — outside the window is structurally invisibleYes — every position is one dot product away
Fails whenThe answer sits further back than the window reachesRarely, for reach — the real cost is §10's quadratic total

Each word dynamically decides which other words to read from, based on their content, not their position. That is the entire idea this page builds.

02Telling position from content

Positional encoding: attention alone can't tell order

Every dot product in this mechanism depends only on the vectors involved, not on where they sit in the sequence — shuffle every token and every Q·K score shuffles identically, unchanged. Without a fix, "dog bites man" and "man bites dog" would attend identically. The fix: add a fixed pattern to each token's embedding before attention runs, built from sines and cosines at different frequencies per dimension — like a clock's hands, several speeds at once, each one bounded and periodic:

PE(pos, 2i) = sin(pos / 10000^(2i/d))    PE(pos, 2i+1) = cos(pos / 10000^(2i/d))
03From one query to every position

Q, K, V: the same retrieval, run for the whole sequence at once

Part 4's query, key, and value were hand-picked vectors. In a real model they're computed from each token's embedding, by three learned matrices: Q = XWQ, K = XWK, V = XWV, where X stacks every token's embedding as a row. Every token gets its own query ("what am I looking for"), its own key ("what do I contain, as advertised to others"), and its own value ("what I'll actually contribute if attended to").

Attention(Q,K,V) = softmax( QKᵀ / √d_k ) V

Read left to right: QKᵀ scores every query against every key at once (Part 1 §04's agreement measure, done n² times in one multiply); divide by √d_k (below); softmax turns each row into a probability distribution over positions; multiplying by V takes the weighted average of values.

Why √d_k, and not "for numerical stability"

Suppose q and k's entries are roughly independent, mean 0, variance 1 — what initialization and layer norm arrange. Their dot product sums d_k independent products; by Part 1 §10's fact, variances add, so the dot product's variance is d_k and its typical size is √d_k. As d_k grows, raw scores grow with it — and a confident softmax has almost no gradient. Dividing by √d_k undoes exactly this growth.

04No peeking

The causal mask

A model predicting the next token must not let position i see positions after it, or it could simply read the answer off. Before softmax, set every score where key position j > i to −∞. Since e⁻∞ = 0, those positions get exactly zero weight — not "very small," exactly zero — while every row still sums to 1, because the mask only redistributes attention among the allowed positions. In code this is a large negative number (like −10⁹) added to the score matrix before softmax, since a literal infinity would produce NaNs.

This is what lets training run on every position of a sequence simultaneously, in one forward pass, while keeping every position honest — a large part of why Transformers train so much faster than the recurrent models they replaced.

05Multiple questions at once

Multi-head attention: several attention patterns in parallel

One attention head can only ask one kind of question per position. The fix: split Q, K, V into h smaller pieces (heads), run the identical attention formula on each piece independently and in parallel, then concatenate the results back together and project once more. Each head is free to specialize — one might track nearby words, another long-range subject-verb agreement — because nothing forces them to learn the same pattern.

MultiHead(Q,K,V) = Concat(head₁, …, head_h) Wᴼ    headᵢ = Attention(QWᵢQ, KWᵢK, VWᵢV)

Total cost is roughly unchanged — you're partitioning capacity among specialists, not adding it. Output shape equals input shape, which is what lets attention operations stack into blocks, next.

06Assembling the block

Attention wrapped in residuals and normalization

One Transformer block is attention (§03–§05) and a small feed-forward network (two linear layers with a kink between them, exactly Part 2's machine), each wrapped in a residual connection and a layer normalization:

x ← x + Attention(LayerNorm(x))    x ← x + FFN(LayerNorm(x))

The residual's +x is Part 2 §10's fix for vanishing gradients — a guaranteed path back to every earlier layer, however deep the stack. LayerNorm rescales each token's vector to have a stable mean and spread before every sub-layer sees it, so training doesn't have to fight ever-drifting activation scales on top of everything else.

Note: this equation uses pre-norm (LayerNorm before each sub-layer) — the now-more-common convention. The original paper used post-norm (LayerNorm after). Both appear in real models; the residual math is identical either way.

07Two shapes, two jobs

Why the original paper used an encoder and a decoder

Translating "the cat sat" into French: to correctly place the feminine adjective ending, the model needs the whole source sentence available at once, with no restriction on looking ahead — there's no "future" in a sentence that's already fully given. But generating the French output must be causal — token 5 can't be produced by peeking at the token-6 answer. One stack can't satisfy both needs at once, so the paper used two: an encoder (full attention, no mask, reads the source once) and a decoder (causal self-attention, generates the target one token at a time).

ArchitectureAccess patternGood atExample
Encoder-onlyBidirectional — every position sees every otherUnderstanding a complete input: classification, fill-in-the-blankBERT
Decoder-onlyCausal — only backwardGenerating one token at a time from what came beforeGPT, and nearly every current LLM
Encoder-decoderBoth, connected by cross-attentionTransforming one full sequence into a different oneTranslation, summarization — T5, MarianMT

Cross-attention: the wire between them

The decoder needs to consult the encoder's finished understanding of the source. Cross-attention is the identical formula from §03 — only the source of Q, K, V changes: Q comes from the decoder's own progress so far, K and V come from the encoder's output. No mask is needed here — the encoder's output is a fully finished, already-complete thing, nothing about it is "in the future."

No mask in cross-attention

The decoder's masked self-attention (one step earlier in the same block) enforces "no looking at the future" — but that rule is about the decoder's own sequence. Cross-attention isn't attending within one sequence at all; it's fusing two different, already-complete ones.

08From numbers to a word

Sampling: turning a distribution into a choice

The stack's final layer produces logits over the vocabulary; softmax turns them into a probability distribution (Part 2 §06). Generation still needs to pick one token from that distribution — always the top pick and text gets repetitive; too random and it stops making sense. Three knobs, all reshaping the same distribution before a token is drawn:

KnobWhat it does
TemperatureDivides logits before softmax — below 1 sharpens toward the top pick, above 1 flattens toward uniform
Top-kZero out every probability outside the k largest, then renormalize and sample
Top-p (nucleus)Keep the smallest set of top candidates whose probabilities sum to p, then sample only from those
09The cost

Attention is quadratic, and everyone cares

Attention computes a score for every pair of positions: n tokens → n² pairs, so attention costs O(n²d) against the feed-forward network's O(nd²). The crossover sits at n = d: below it, the FFN is the bottleneck; above it, the quadratic term takes over and never lets go — double the context, attention quadruples.

That single fact drives an enormous amount of downstream engineering: FlashAttention (identical maths, tiled so the n×n matrix never touches slow memory), sliding-window and sparse attention, and state-space models like Mamba.

KV caching. When generating one token at a time, earlier tokens' keys and values never change — so cache them. Each new token then costs O(nd) rather than O(n²d). This is a different mechanism from §07's encoder K/V reuse — this cache is for the decoder's own self-attention.

10Reference

Traps and a cheatsheet

Symptom / questionResolution
"Isn't cross-attention just self-attention?"Same formula, different sourcing — K/V from the encoder, Q from the decoder. Self-attention never mixes two different sequences.
"Why no mask in cross-attention?"Masking enforces autoregression within one sequence. Cross-attention fuses two already-complete ones.
Output looks repetitive / stuck in a loopTemperature too low, or top-k/top-p too narrow
Output looks incoherentTemperature too high, or top-p threshold too generous
"Which should I use, top-k or top-p?"Top-k is simpler and predictable; top-p adapts its eligible set to the model's confidence — usually the better default
11Practice

Exercises

  1. Why can't a decoder-only model translate a full sentence the way an encoder-decoder can, even given unlimited training data?
  2. Temperature is set to 0.01. What happens to generation, and why?
  3. You set top-k = 1. What sampling strategy have you accidentally reproduced?
Answers
  1. It can only ever look backward. Resolving "it" in §01's example requires a word that comes later — structurally invisible to a purely causal model, no matter how much data it sees.
  2. Generation becomes almost perfectly deterministic — the highest-logit word gets pushed to probability ≈1.
  3. Greedy decoding — always take the single highest-probability word, with no randomness at all.
